# Test requirements -- agent UX (phases 1-5)

This document maps every acceptance criterion from the [agent UX design](../../design-plans/2026-02-16-agent-ux.md) to its test coverage. Each criterion appears in exactly one of three sections: automated test coverage (phases 1-5), human verification required, or deferred criteria (phases 6-8).

## Human verification required

| Criterion                                 | Why Not Automated                                                                                                                                          | Verification Approach                                                                                                                                                                                                                                                                                 |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| agent-ux.AC4.1 (Deno sandbox end-to-end)  | Requires Deno binary installed in the test environment. CI may not have Deno.                                                                              | Sandbox integration tests are marked with `@pytest.mark.skipif(not shutil.which("deno"), reason="Deno not installed")`. Manual verification: run sandbox tests in a Docker container with Deno installed (matching production image). Verify code executes, tool calls route, and output is returned. |
| agent-ux.AC4.5 (memory limit enforcement) | V8 memory limits are enforced by the Deno runtime, not by Python code. The automated test only verifies the flag is passed.                                | Manual verification: run a Deno sandbox script that allocates memory beyond the limit and confirm the process is killed by V8 with an out-of-memory error.                                                                                                                                            |
| agent-ux.AC5.1 (live SSE stream)          | `django-eventstream` SSE connections require a running ASGI server with Redis pub/sub. The Django test client does not support long-lived SSE connections. | Manual verification: start the full stack (`docker compose up`), open an `EventSource` connection to the SSE endpoint in a browser or via `curl`, trigger an agent run, and confirm events stream in real-time. Verify both run-level and conversation-level channels deliver events.                 |
| agent-ux.AC5 (connection drop recovery)   | SSE reconnection is a client-side (frontend) concern that requires a live SSE connection to test.                                                          | Manual verification: open an SSE connection, disconnect it (network interruption or server restart), reconnect, and confirm the catch-up fetch returns all missed activities before the stream resumes.                                                                                               |
| agent-ux.AC3.4 (full multi-turn)          | True multi-turn verification requires an actual LLM call where the second response references the first exchange. Automated tests mock the LLM.            | Manual verification: start a conversation with the built-in agent, send two messages, and verify the second response accounts for the first exchange. Inspect conversation messages in the database to confirm context is passed correctly.                                                           |
| agent-ux.AC4.9 (stale detection timing)   | The Celery beat schedule (`detect_stale_agent_runs` every minute) requires a running Celery beat process to verify timing.                                 | Manual verification: create an in-progress agent run, wait for the stale timeout, and confirm Celery beat marks it as stale. Automated test calls the function directly (verifying logic, not scheduling).                                                                                            |

## Deferred criteria (phases 6-8)

The following acceptance criteria are NOT covered by phases 1-5. They will be addressed in a second implementation plan round covering phases 6 (agent management UI), 7 (agent mention autocomplete), and 8 (agent chat UI).

### agent-ux.AC1: Agent management UI

| Criterion           | Phase | Reason Deferred                                                                                                                                                                                                                               |
| ------------------- | ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| agent-ux.AC1.1      | 6     | Workspace settings "Agents" page listing is a frontend UI component.                                                                                                                                                                          |
| agent-ux.AC1.2      | 6     | External agent registration modal and API token display are frontend concerns. The backend API already exists (pre-existing `AgentProfileViewSet`).                                                                                           |
| agent-ux.AC1.3      | 6     | Agent detail page with editable configuration and runs table is a frontend component.                                                                                                                                                         |
| agent-ux.AC1.4 (UI) | 6     | The built-in agent card display, configuration options UI (model override, tool permissions, active toggle), and cannot-be-deleted constraint in the UI are frontend concerns. The backend seed (phase 1) and model constraints support this. |
| agent-ux.AC1.5 (UI) | 6     | The deactivation toggle UI and its effect on the mention dropdown are frontend concerns. The backend routing logic (phase 4) already skips inactive agents.                                                                                   |
| agent-ux.AC1.6      | 6     | "Not authorized" message for non-admin users accessing the agents settings page is a frontend permission gate.                                                                                                                                |
