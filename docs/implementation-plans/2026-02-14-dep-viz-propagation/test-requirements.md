# Dependency Visualization and Date Propagation — Test Requirements

## Overview

This document maps every acceptance criterion from the dependency visualization and date propagation design (`dep-viz-propagation.AC1` through `dep-viz-propagation.AC7`) to either an automated test or a documented human verification approach. The mapping is rationalized against the implementation decisions in phases 1 through 7. There are 48 total acceptance criteria across 7 feature areas.

### Rationale for Human Verification Criteria

All 12 human verification criteria fall into two categories:

1. **Visual rendering correctness** (AC3.3, AC3.4, AC3.5, AC6.2, AC6.3, AC7.2, AC7.3, AC7.4): These require confirming that SVG elements, CSS classes, tooltips, and visual treatments render correctly in a real browser. While the underlying data and logic are unit-tested (path calculation, conflict detection, state management), the final visual output depends on browser rendering engines, CSS resolution, and SVG rendering which cannot be meaningfully verified in JSDOM.

2. **Interactive drag behavior** (AC4.1, AC4.5, AC4.6, AC4.8): These require real mouse event sequences, CSS hover pseudo-class activation, real-time coordinate tracking, and visual feedback that depends on browser layout calculations. The underlying logic (type inference, cycle detection, state management) is unit-tested, but the interactive experience requires manual verification.
