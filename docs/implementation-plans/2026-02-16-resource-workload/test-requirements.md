### Notes on test strategy

1. **Backend-heavy testing.** The aggregation logic (Phase 3) and CRUD endpoints (Phases 1, 2, 6) are thoroughly tested via unit and contract tests. All edge cases (multi-assignee splitting, missing estimates, missing capacity, threshold boundaries) have dedicated automated tests.

2. **Frontend components require human verification.** The workload view (Phase 4), Gantt indicators (Phase 5), and worklog UI stubs (Phase 6) are primarily visual/interactive. Their correctness depends on colour rendering, layout proportions, click interactions, and reactive updates that cannot be meaningfully automated without a full browser-based E2E framework. The implementation plans specify `pnpm check:types` as the primary automated verification for frontend components.

3. **CE stubs are verified structurally.** The HW/CE overlay pattern means CE stubs must satisfy the same TypeScript interface as HW implementations. `pnpm check:types` catches any interface mismatch at build time, making runtime tests redundant for the "renders null" behaviour.

4. **Phase 7 (stretch) is fully testable.** The `analyzeLevelling` pure function follows the same pattern as `cpm-calculator.ts` and `dependency-conflict.ts`, both of which have comprehensive Vitest test suites.
